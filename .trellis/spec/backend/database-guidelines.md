# Data Persistence Guidelines

> How EoH stores runtime state, checkpoints, diagnostics, and experiment artifacts without a database.

---

## Overview

EoH is fully file-backed. There are no SQL, NoSQL, or ORM layers anywhere in the core package. Persistence falls into three buckets:

- Core runtime snapshots under `{exp_output_path}/results/`
- Example- or workflow-specific artifact trees such as `experiments/results/<run-id>/...`
- Dataset/test fixtures stored as pickle, plain text, or domain-specific assets

The entry point that creates the base runtime directories is still `create_folders()`:

```python
# eoh/src/eoh/utils/createFolders.py:3-20
def create_folders(results_path):
    folder_path = os.path.join(results_path, "results")
    if not os.path.exists(folder_path):
        os.makedirs(folder_path)

    subfolders = ["history", "pops", "pops_best"]
    for subfolder in subfolders:
        subfolder_path = os.path.join(folder_path, subfolder)
        if not os.path.exists(subfolder_path):
            os.makedirs(subfolder_path)
```

`EVOL.__init__()` also persists a sanitized experiment config immediately:

```python
# eoh/src/eoh/eoh.py:23-28
_sensitive = {"llm_api_key", "llm_local_url"}
config = {k: v for k, v in vars(paras).items() if k not in _sensitive}
config_path = os.path.join(paras.exp_output_path, "config.json")
with open(config_path, "w") as f:
    json.dump(config, f, default=str, indent=2)
```

## Storage Formats

| Format | Purpose | Where |
|--------|---------|-------|
| JSON | Generation checkpoints, best-individual snapshots, sanitized config, seed selections | `{exp_output_path}/results/`, `{exp_output_path}/config.json`, `examples/user_abr/seed_cache/` |
| JSONL | Timeout diagnostics | Path chosen by `exp_timeout_diagnostics_path` |
| Pickle | Problem-instance fixtures and evaluation datasets | `examples/*/testingdata/`, `examples/*/TrainingData/` |
| Plain text | Evaluation summaries and logs | `results.txt`, workflow log files |
| PNG/PDF/DOCX | Reports and plots | Generated by analysis/report utilities |

## Core Runtime Output Tree

For the baseline framework, `Paras.exp_output_path` points to an experiment root. `create_folders()` then adds the `results/` subtree beneath it:

```
{exp_output_path}/
├── config.json
└── results/
    ├── history/
    ├── pops/
    │   ├── population_generation_0.json
    │   ├── population_generation_1.json
    │   └── ...
    └── pops_best/
        ├── population_generation_1.json
        └── ...
```

Generation zero is written either after seed evaluation or after the initial random/operator-based population build:

```python
# eoh/src/eoh/methods/eoh/eoh.py:107-114
if self.use_seed:
    with open(self.seed_path) as file:
        data = json.load(file)
    population = interface_ec.population_generation_seed(data, self.exp_n_proc)
    filename = self.output_path + "/results/pops/population_generation_0.json"
    with open(filename, 'w') as f:
        json.dump(population, f, indent=5)
```

```python
# eoh/src/eoh/methods/eoh/eoh.py:145-148
filename = self.output_path + "/results/pops/population_generation_0.json"
with open(filename, 'w') as f:
    json.dump(population, f, indent=5)
```

Normal generation checkpoints are written here:

```python

filename = self.output_path + "/results/pops/population_generation_" + str(pop + 1) + ".json"

with open(filename, 'w') as f:

```

## Population JSON Contract

### Full-population snapshot

The full checkpoint is a JSON array of individual dicts. The exact in-memory shape comes from `_empty_offspring()` and `population_generation_seed()`:

```python
# eoh/src/eoh/methods/eoh/eoh_interface_EC.py:12-18
def _empty_offspring():
    return {
        'algorithm': None,
        'code': None,
        'objective': None,
        'other_inf': None
    }
```

```python
# eoh/src/eoh/methods/eoh/eoh_interface_EC.py:251-263
seed_alg = {
    'algorithm': seeds[i]['algorithm'],
    'code': seeds[i]['code'],
    'objective': None,
    'other_inf': None
}
obj = float(fitness[i])
seed_alg['objective'] = float(np.round(obj, 5))
seed_alg['other_inf'] = other_infs[i]
population.append(seed_alg)
```

Persisted shape:

```json
[
  {
    "algorithm": "Natural-language description used in prompts",
    "code": "Python source code for the evolved heuristic",
    "objective": 0.12345,
    "other_inf": "Optional evaluator feedback string or null"
  }
]
```

### Best-individual snapshot

`pops_best/population_generation_N.json` is a single dict, not an array, because `EOH.run()` writes `population[0]` directly.

### Serialization settings

- Population snapshots use `indent=5`
- Config snapshots use `indent=2` plus `default=str`
- Timeout diagnostics use one JSON object per line with sorted keys

## Checkpoint and Resume Patterns

### Seed-based initialization

`Paras` exposes a dedicated seed-loading path:

```python
# eoh/src/eoh/utils/getParas.py:38-45
self.exp_use_seed = False
self.exp_seed_path = "./seeds/seeds.json"
self.exp_use_continue = False
self.exp_continue_id = 0
self.exp_continue_path = "./results/pops/population_generation_0.json"
self.exp_n_proc = 1
self.exp_timeout_diagnostics = False
self.exp_timeout_diagnostics_path = None
```

At runtime, seed files are evaluated into generation zero:

```python
# eoh/src/eoh/methods/eoh/eoh_interface_EC.py:235-271
def population_generation_seed(self, seeds, n_p):
    if hasattr(self.interface_eval, "evaluate_with_details"):
        results = Parallel(n_jobs=n_p)(
            delayed(self.interface_eval.evaluate_with_details)(seed["code"])
            for seed in seeds
        )
    else:
        fitness = Parallel(n_jobs=n_p)(
            delayed(self.interface_eval.evaluate)(seed["code"]) for seed in seeds
        )
```

### Continue-from-checkpoint

The continue path loads a prior checkpoint file and resumes from `exp_continue_id`:

```python
# eoh/src/eoh/methods/eoh/eoh.py:116-123
if self.load_pop:
    print("load initial population from " + self.load_pop_path)
    with open(self.load_pop_path) as file:
        data = json.load(file)
    for individual in data:
        population.append(individual)
    print("initial population has been loaded!")
    n_start = self.load_pop_id
```

Use that when a checkpoint already contains evaluated objectives and should be treated as the active starting population.

## Canonical ABR Experiment Tree

The ABR workflow does not leave final outputs in `examples/user_abr/` or the repo-root `results/`. It computes a canonical per-run tree first:

```python
# examples/user_abr/runEoH.py:227-235
dataset = os.environ.get("DATASET", "FCC-18")
output_name = os.environ.get("ABR_OUTPUT_NAME", dataset)
run_layout = build_run_layout(repo_root)
output_root = build_eoh_output_root(repo_root, output_name=output_name, run_id=run_layout.run_id)
timeout_diagnostics_path = build_log_path(
    repo_root,
    log_name="timeout_diagnostics",
    run_id=run_layout.run_id,
)
```

Resulting layout:

```
experiments/results/<run-id>/
├── raw/
│   └── eoh/
│       └── <output-name>/
│           └── eoh_<Problem>_<timestamp>/
│               ├── config.json
│               └── results/
│                   ├── history/
│                   ├── pops/
│                   └── pops_best/
├── analysis/
└── logs/
```

That means the same core `results/pops/` schema still applies, but it now lives inside a canonical run-specific root.

## Seed Cache and Re-Evaluation Pattern

Unlike the older baseline examples, `examples/user_abr/` deliberately persists reusable seed populations:

```python
# examples/user_abr/runEoH.py:259-277
cache_dir = _build_seed_cache_dir(dataset, seed_mode_slug)
cache_file = cache_dir / "population_generation_0.json"
use_cache = cache_file.exists() and not _env_flag("SEED_NO_CACHE")

fitness_mode = os.environ.get("ABR_FITNESS_MODE", "mean").strip().lower()
if use_cache and fitness_mode != "mean":
    cache_file = _reevaluate_cached_population(cache_file, problem, fitness_mode)
```

When fitness mode changes, the cache is not trusted blindly. A temporary re-evaluated file is written under a sibling `_reevaluated/` directory:

```python
# examples/user_abr/runEoH.py:207-214
reeval_dir = cache_file.parent / "_reevaluated"
reeval_dir.mkdir(parents=True, exist_ok=True)
reeval_file = reeval_dir / f"population_generation_0_{fitness_mode}.json"
with open(reeval_file, "w") as fh:
    json.dump(population, fh, indent=5)
```

This is still file-based persistence, but it is cache persistence rather than canonical run output.

## Caching

There is no generalized database or key-value cache layer. Persistence remains explicit files on disk.

What does exist:

- HTTP-level cache disabling for remote LLM transport:

```python
# eoh/src/eoh/llm/api_general.py:43-48
headers = {
    "Authorization": "Bearer " + self.api_key,
    "User-Agent": "Apifox/1.0.0 (https://apifox.com)",
    "Content-Type": "application/json",
    "x-api2d-no-cache": 1,
}
```

- Example-specific seed-cache reuse in `examples/user_abr/`

Do not describe the project as "no caching exists" anymore; the accurate statement is "no centralized cache service exists".

---

## Conventions for New Code

1. Prefer JSON for structured runtime artifacts and keep schemas stable across generations.
2. Keep the individual contract consistent: `algorithm`, `code`, `objective`, `other_inf`.
3. Persist generation checkpoints eagerly so runs can be resumed or inspected without replaying the full search.
4. Use separate files for canonical outputs and caches; do not mix reusable seed caches into the final experiment bundle.
5. Keep sensitive fields out of persisted config snapshots.
6. Do not introduce a database dependency just to store experiment results.
