# Data Persistence Guidelines

> How data is stored and persisted in the EoH project.

---

## Overview

EoH does **not use any database**. There are no SQL, NoSQL, or ORM dependencies. All data persistence is **file-based**, using JSON as the primary format and pickle for problem instance data.

---

## Storage Formats

| Format | Purpose | Where |
|--------|---------|-------|
| **JSON** | Population snapshots, seed files, individual results | `results/pops/`, `results/pops_best/` |
| **Pickle** | Problem instance data (training/testing datasets) | `examples/*/testingdata/`, `examples/*/TrainingData/` |
| **Plain text** | Evaluation result summaries | `results.txt` in evaluation folders |
| **PNG/PDF** | Convergence plots | Generated by `createReport.py` |
| **DOCX** | Experiment reports | Generated by `createReport.py` |

---

## Output Directory Structure

Created by `eoh/src/eoh/utils/createFolders.py` at startup:

```
{exp_output_path}/results/
├── history/           # Created but currently unused (writing commented out)
├── pops/              # Full population snapshot per generation
│   ├── population_generation_0.json
│   ├── population_generation_1.json
│   └── ...
└── pops_best/         # Best individual per generation
    ├── population_generation_1.json
    └── ...
```

Default `exp_output_path` is `"./"` (current working directory).

---

## JSON Population Schema

Each generation writes a JSON array of individuals:

```json
[
     {
          "algorithm": "Description of the heuristic in natural language",
          "code": "def heuristic(...):\n    ...\n    return result",
          "objective": 0.12345,
          "other_inf": null
     }
]
```

The `pops_best/` variant contains a single individual (not wrapped in an array).

JSON is written with `indent=5`:

```python
# eoh/src/eoh/methods/eoh/eoh.py:170-172
with open(filename, 'w') as f:
    json.dump(population, f, indent=5)
```

## Checkpoint/Resume Mechanism

### Seed Population

Load pre-defined heuristics to initialize the population:

```python
# Set in Paras
paras.set_paras(
    exp_use_seed=True,
    exp_seed_path="./seeds/seeds.json"
)
```

Seed JSON format: array of `{"algorithm": ..., "code": ...}` objects.

### Continue from Checkpoint

Resume evolution from a saved population:

```python
# Set in Paras
paras.set_paras(
    exp_use_continue=True,
    exp_continue_id=5,        # Generation to resume from
    exp_continue_path="./results/pops/population_generation_5.json"
)
```

---

## Caching

**No caching mechanisms exist.** The LLM API client explicitly disables upstream caching:

```python
# eoh/src/eoh/llm/api_general.py:28
"x-api2d-no-cache": 1
```

Problem instances are loaded into memory at initialization and kept for the duration of the run.

---

## Conventions for New Code

1. **Use JSON for structured data** -- maintain consistency with existing population files
2. **Use pickle only for large binary data** (numpy arrays, instance datasets)
3. **No databases** -- do not introduce SQLite, Redis, or any DB dependency
4. **Write results per generation** -- enables checkpoint/resume and progress monitoring
5. **No file I/O error handling needed in the core loop** -- the framework assumes the output directory exists (created at startup)
6. **Use `indent=5`** for JSON output to match existing files
