## Context

EoH (Evolution of Heuristics) is a Python framework combining Evolutionary Computation with LLMs for automatic algorithm design. Core source: `eoh/src/eoh/`.

### Architecture Overview

| Module | Core Class | Responsibility |
|--------|-----------|----------------|
| `eoh.py` | `EVOL` | Entry orchestrator: init → Probs → Methods → run() |
| `methods/methods.py` | `Methods` | Factory: selects EOH/AEL/LS/FunSearch/ReEVO by `paras.method` |
| `methods/eoh/eoh.py` | `EOH` | Main evolution loop: init pop → iterate (select→mutate→eval→manage) |
| `methods/eoh/eoh_evolution.py` | `Evolution` | LLM prompt construction + response parsing (i1/e1/e2/m1/m2/m3 operators) |
| `methods/eoh/eoh_interface_EC.py` | `InterfaceEC` | EC interface: parallel eval, timeout diagnostics, population mgmt |
| `llm/interface_LLM.py` | `InterfaceLLM` | LLM router (remote API / local deployment) |
| `llm/api_general.py` | `InterfaceAPI` | HTTP requests with retry, timeout, exponential backoff |
| `problems/problems.py` | `Probs` | Problem loader factory (TSP, BP, or custom) |
| `utils/getParas.py` | `Paras` | Global parameter config with `set_paras(**kwargs)` |

### Key Patterns to Document

1. **Evolution Operator System**: 6 operators (i1, e1, e2, m1, m2, m3) each with different prompt templates and parent selection strategies. Operators are configurable via `ec_operators` and `ec_operator_weights`.

2. **Timeout Diagnostics System**: Three-layer timeout tracking (LLM request → LLM total phase → evaluation subprocess → parallel worker budget). Records written to JSONL with structured `_diagnostic_record()`.

3. **Evaluation Pipeline**: Code generated by LLM → optional numba decoration → subprocess-based evaluation with `multiprocessing.Process` + `Queue` → fitness extraction.

4. **Selection/Management Strategy Pattern**: Pluggable selection (`prob_rank`, `equal`, `roulette_wheel`, `tournament`) and management (`pop_greedy`, `ls_greedy`, `ls_sa`) chosen at runtime.

5. **LLM Response Parsing**: Regex-based extraction of algorithm description `{...}` and code blocks `import...return` from LLM output.
